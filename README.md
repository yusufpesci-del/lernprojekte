# Lernprojekte

Mein Weg vom Projektingenieur (Sprinkleranlagen, Brandschutz) zum
Softwareentwickler. Hier liegt alles, was dabei entsteht — Übungen,
kleine Programme, Notizen.

Öffentlich, weil es mich ehrlich hält. Jeder Commit ist ein Lerntag.

## Was wo liegt

| Datei / Ordner | Inhalt |
|---|---|
| `cs50p/` | Harvard CS50P, nach Wochen sortiert |
| `cs50p/wiederholung/` | selbstgestellte Aufgaben zum Festigen |
| `spickzettel.md` | alles Gelernte zum Nachschlagen, mit meinen eigenen Fehlern |
| `erklaert.md` | mein Code, Zeile für Zeile auf Deutsch kommentiert |
| `lernplan.md` | der Plan bis zur Bewerbungsreife |
| `log.md` | Lerntagebuch, ein Eintrag pro Lerntag |

## Stand

**CS50P Woche 0 bis 4 durch, Problem Set 0 bis 3 vollständig gelöst.**
Als Nächstes Problem Set 4.

Gelernt bisher: Variablen und Datentypen, Bedingungen, Schleifen, Listen,
Dictionaries, Funktionen, Fehler abfangen mit `try`/`except`,
fremde Bibliotheken einbinden (`import`, `pip`), Dienste im Netz abfragen,
eigene Module, Fehlermeldungen lesen, Git.

Ab Problem Set 3 heißen die Variablen **englisch**. Das Ziel ist der
US-Arbeitsmarkt, die Dokumentation ist englisch — und zwei Sprachen in
einer Datei zu mischen wird nur unübersichtlich.

## Wohin das führt

1. **CS50P fertig** — bis Mitte Dezember
2. **Ein Werkzeug zur Sprinklerauslegung nach FM-Regelwerk** — das
   eigentliche Projekt. Führt den Fachplaner per Ja/Nein-Fragen von der
   Einstufung bis zur Auslegung. CS50P machen jedes Jahr zehntausende;
   das hier gibt es einmal.
3. **Im Browser benutzbar machen** — HTML, CSS, FastAPI, SQL
4. **Bewerbungsreife** — bevorzugt USA

## Regeln, die ich mir gesetzt habe

- Den Code schreibe ich selbst. KI erklärt, korrigiert und stellt Fragen —
  sie tippt nicht für mich.
- Jeder Lerntag endet mit einem Eintrag in `log.md` und einem Commit.
- Fehler bleiben dokumentiert statt still korrigiert. Die Stolpersteine im
  Spickzettel sind der nützlichste Teil davon.
